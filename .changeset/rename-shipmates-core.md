Renamed from `kenning` to `shipmates` (spec D38). This package was published as `kenning` up to 0.1.1; it continues here, and `kenning` is deprecated. What users must change: install `shipmates` instead of `kenning` (`npm i -g shipmates`; the CLI is now `shipmates`), import from `shipmates`, and rename the environment variable `KENNING_STATE_DIR` to `SHIPMATES_STATE_DIR` (the other `KENNING_*` variables are read by the extension, see `@shipmates/pi`). The state now lives in `$XDG_STATE_HOME/shipmates/shipmates.db` (was `$XDG_STATE_HOME/kenning/kenning.db`), and nothing reads the old path: to keep existing data, stop every session, move `$XDG_STATE_HOME/kenning/` to `$XDG_STATE_HOME/shipmates/`, and rename `kenning.db`, `kenning.db-wal` and `kenning.db-shm` in it to `shipmates.db`, `shipmates.db-wal` and `shipmates.db-shm`. For hosts: the exported names are `Shipmates`, `openShipmates`, `ShipmatesError`, `ShipmatesHost` and `ShipmatesOptions` (were `Kenning...`), the host registry key is `Symbol.for('shipmates.host')` (was `kenning.host`), and the human-input events are `shipmates:human-input` and `shipmates:human-input-end` (were `kenning:...`).
