# Provenance protects against confused agents, not against a malicious one on the same Unix user

**Status:** accepted (2026-11-17); amended 2026-11-18 (mark expiry, `pi -p`, spawned sessions)

Every message records `human`, `agent` or `human-relayed`, and safety gates accept only the first and the last. On one Unix user an agent's `bash` can write kenning's database or run its CLI, so kenning cannot make human origin unforgeable. What it guarantees is that no kenning tool lets an agent claim it, and that forging it means deliberately bypassing kenning.

Human acts are recognised only from channels an agent cannot reach through kenning: typing in the TUI (`input` with `source: "interactive"`), a kenning slash command (the model cannot invoke slash commands), the CLI only with a TTY and without `PI_SESSION_FILE` (pi sets it in the bash tool's environment), and a host's explicit mark: before sending a human's text, a host emits `kenning:human-input` `{text, channel}` on the session's `pi.events` bus, which only extension code can reach, and kenning records the next matching input as a human turn. A mark is valid for 5 s after it is emitted and is then dropped, never matched: the host emits it immediately before the send (measured mark-to-`input` latency on pi 1.4: about 0.1 ms), and a mark whose send never reached kenning's `input` handler (another extension handled it, pi refused it while compacting) must not turn a later identical `extension` input, such as a scheduled job's prompt, into a human turn (D22). A host that awaits its send also emits `kenning:human-input-end` `{text, id?}` once the send settles, which closes the mark with no window (D35); the expiry remains the backstop for a host whose send is fire-and-forget. The upstream change that would retire the mark is proposed as earendil-works/pi#12291. `pi -p` reports its prompt as `interactive` too, so outside the TUI an `interactive` input is the human's only under the CLI's rule: a terminal, and no `PI_SESSION_FILE` (D27). A session spawned by another gets its first prompt as an `agent` message from its owner, never as a human turn (D28). `human-relayed` must name such a turn (`relayOf`), and the receiver gets the human's verbatim words with it, not the agent's paraphrase.

**Rejected:** claiming the strong guarantee (false on one user). Reserved for later: a signature by a host that runs as another user (wherever as a NixOS system service), and an upstream pi change that carries an origin on `prompt()` / `sendUserMessage` and stores it on the user entry.
